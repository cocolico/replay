# 双臂标定交付文件

主文件：handeye_calibration.json。其余文件用于说明和复核。

## 当前可以做什么

已具备相机彩色 optical 坐标与左右机械臂基坐标之间的固定变换，可用于后续视觉目标或 EEF 位姿的坐标转换。
左右臂各有 10 组求解样本，27 份原始样本离线检查通过；每侧另有 3 个未参与求解的新姿态检查。
新姿态位置差 RMS：左 1.393 mm、右 1.128 mm；最大位置差：左 1.677 mm、右 1.285 mm。
左臂采用重新安装后的单帧参考关系，右臂采用原求解板安装关系；这些是相机与运动学的一致性检查，不能当作绝对定位精度。

## 文件已经包含

- 左右基座相对相机的 4×4 外参、逆变换、左右基座间的派生变换。
- 米制单位、矩阵排列、变换方向、机器人身份和相机 optical frame。
- 1280×800 彩色图像的内参与 8 个畸变系数，以及适用范围。
- 标定板规格、求解方法、样本数量、验证数值和已知限制。
- 后续 EEF 文件需要明确的字段与坐标转换公式。

原始采集数据保留在旁边的 calibration_data 目录，不随这个轻量交付包重复复制。复核报告和原始文件校验和随包提供。
仓库自带的原作者静态 TF 文件及 world_frame.json 不属于本次标定结果，不应混用。

## EEF 文件接入规则

你确认将来文件存储末端位姿，目前没有文件，任务尚未确定，因此现在只能确认坐标转换所需的标定信息已具备。
EEF 文件必须明确：左右臂、参考坐标系、控制的是法兰/配置末端/具体 TCP、长度与旋转单位、绝对位姿或相对增量；轨迹还要有时间与顺序。
建议将绝对位姿直接存成 4×4 矩阵，减少欧拉角/四元数约定歧义；如果已有格式，按实际格式适配。

- 若文件已在对应机械臂底座系下，不要重复乘相机外参。
- 若文件为 camera_T_tcp：base_T_tcp = base_T_camera @ camera_T_tcp。
- 若控制器要求法兰目标：base_T_flange = base_T_tcp @ inverse(flange_T_task_tcp)。
- 文件若是相对位姿增量，还要知道增量在哪个坐标系表达、左乘还是右乘；不能当作绝对位姿直接转换。

采样时配置末端坐标与法兰重合。装回 Sharpa 后，抓取点/指尖通常不是法兰原点，不能把采样时的单位矩阵当作任务 TCP 标定。
JSON 中 flange_T_task_tcp 目前为 null，表示尚未确定，不能用零偏移代替。

## 缺项检查与后续任务判断

| 项目 | 状态 | 后续影响 |
|---|---|---|
| 左右臂外参及坐标约定 | 已有，离线复核通过 | 可做固定坐标转换 |
| EEF 文件及格式定义 | 尚无 | 无法确认解析和坐标语义兼容 |
| 实际工具 TCP | 尚未校准/提供 | 无法确认指尖或抓取点的位置 |
| 具体任务与允许误差 | 未确定 | 无法认定现有精度满足任务 |
| 工具实际对点测试 | 未完成 | 没有实际定位精度验收 |
| 深度尺度/彩深对齐 | 未验证，未保存深度图 | 使用 RGB-D 目标定位时需补验 |
| IK、碰撞、速度/加速度和控制环境 | 本次未验收 | 外参正确不代表轨迹可执行 |

结论：该标定文件可以作为后续 EEF 坐标转换的依据；尚不能保证任何尚未定义的任务自动完成。
如果任务是同底座下的已知末端位姿回放，相机外参可能根本不参与；若是视觉抓取，则还需要目标三维定位、抓取姿态、TCP 和路径执行。
